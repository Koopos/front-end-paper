##  强制类型转换

如上所述，JavaScript 是一门**弱类型**语言。这意味着你可以经常使用与预期类型不同的类型的值，JavaScript 语言将为你把它转换为正确的类型。为此，JavaScript 定义了一些强制转换规则。



在 JavaScript 中，使用双等号 `==`（松散相等）进行比较时，如果两边的类型不一致，JS 会进行**隐式强制类型转换**。

这套转换逻辑遵循 **Abstract Equality Comparison Algorithm**。虽然听起来很复杂，但核心逻辑通常是：**“尽量往数字（Number）转”**。

---

### 1. 核心转换规则表

当 `x == y` 时，JS 的处理优先级如下：

| **类型 X**  | **类型 Y**               | **转换行为**                                                |
| --------- | ---------------------- | ------------------------------------------------------- |
| `null`    | `undefined`            | **true** (它们互相相等，且不等于其他任何值)                             |
| `Number`  | `String`               | 将 **String** 转为 **Number**                              |
| `Boolean` | `Any`                  | 将 **Boolean** 转为 **Number** (true -> 1, false -> 0)     |
| `Object`  | `String/Number/Symbol` | 将 **Object** 转为 **原始值** (调用 `valueOf()` 或 `toString()`) |

---

### 2. 常见的“坑”与典型案例

理解了上面的规则，这些奇怪的现象就好解释了：

#### A. 字符串与数字

JavaScript

```
"42" == 42 // true
// 逻辑：字符串 "42" 转成数字 42
```

#### B. 布尔值的陷阱（最容易出错）

JavaScript

```
"2" == true // false
```

> **解释：** 很多人以为 `"2"` 是真值，所以应该相等。但规则是：`true` 先转成 `1`。然后变成 `"2" == 1`，接着 `"2"` 转成 `2`。最终 `2 == 1` 为 `false`。

#### C. 对象转原始值

JavaScript

```
[1, 2] == "1,2" // true
```

> **解释：** 数组是对象，会先调用其 `toString()` 方法。`[1, 2].toString()` 结果是 `"1,2"`，两边相等。

#### D. null 与 undefined 的特殊性

null 跟数字比较强制转成数字 NaN NaN == 0 所以是false


JavaScript

```
null == undefined // true
null == 0         // false
undefined == 0    // false
```

> **注意：** `null` 和 `undefined` 在 `==` 下只认彼此（和自身），不会被转成数字 `0`。
