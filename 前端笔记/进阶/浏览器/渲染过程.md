浏览器渲染（Rendering）是将 HTML、CSS 和 JavaScript 转换成屏幕上像素点的复杂过程。为了让你直观理解，我们可以把这个过程想象成**“从施工图纸到精装房”**的建设过程。

以下是主流浏览器（如 Chrome）的渲染流水线：

---

### 1. 解析 HTML 生成 DOM 树

浏览器从网络接收到 HTML 原始字节，将其转换为字符串，再解析成一个个“节点”（Node）。这些节点最终构成了一棵 **DOM（Document Object Model）树**。

- **关键点：** 这是网页的骨架。
    

### 2. 解析 CSS 生成 CSSOM 树

浏览器同时会解析 CSS 文件或 style 标签内的样式，生成 **CSSOM（CSS Object Model）树**。

- **关键点：** 浏览器需要知道每个节点的样式规则。
    

### 3. 构建渲染树 (Render Tree)

将 DOM 树和 CSSOM 树合并。渲染树只包含**可见**的节点（例如，`display: none` 的元素不会出现在这里，而 `visibility: hidden` 的会）。

- **关键点：** 渲染树确定了页面上最终要显示的结构和样式。
    

### 4. 布局 (Layout / Reflow)

浏览器根据渲染树，计算出每个节点在屏幕上的确切**几何位置**和**大小**。

- **关键点：** 这一步处理的是坐标和盒子模型（Box Model）。
    

### 5. 分层与绘制 (Layering & Painting)

为了处理 3D 转换、滚动条或 z-index，浏览器会将页面拆分成多个“图层”。

- **绘制 (Paint)：** 将每个图层的样式（背景、边框、文字颜色等）转换成具体的像素指令。
    

### 6. 合成 (Composition)

这是最后一步。浏览器将之前生成的各个图层发送给 GPU（显卡），由 GPU 将它们合成为一张最终的位图并显示在你的屏幕上。

- **优点：** 使用 GPU 合成图层非常快，这也是为什么现代浏览器滑动起来很流畅的原因。
    

---

### 💡 为什么你的网页会卡顿？

有两个核心概念需要注意：

1. **回流 (Reflow)：** 当你改变元素的几何属性（如宽、高、位置）时，浏览器必须重新执行“布局”及其后续步骤。**开销极大**。
    
2. **重绘 (Repaint)：** 当你只改变外观（如背景颜色、文字颜色）而不影响布局时，浏览器跳过布局直接“绘制”。**开销较小**。
