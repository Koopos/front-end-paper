“前端性能”其实可以理解为一句话👇

> 👉 **让页面“更快出现 + 更快可用 + 更流畅”**

我给你一套**系统化 + 实战导向**的总结（也是面试高频框架）👇

---

# 🧠 一、前端性能优化三大核心

## 1️⃣ 加载性能（Load）

👉 页面多久能看到内容（解决白屏）

---

## 2️⃣ 渲染性能（Render）

👉 页面渲染是否顺畅

---

## 3️⃣ 交互性能（Runtime）

👉 点击、滚动是否卡顿

---

# 📊 二、核心性能指标（必须知道）

## 👉 Web 性能指标（行业标准）

- **FCP（First Contentful Paint）**  
    👉 首次出现内容（白屏结束）
    
- **LCP（Largest Contentful Paint）**  
    👉 最大内容加载完成
    
- **TTI（Time to Interactive）**  
    👉 页面可交互时间
    
- **CLS（Cumulative Layout Shift）**  
    👉 页面是否乱跳
    

---

👉 一句话总结：

- FCP/LCP → 看“快不快”
    
- TTI → 看“能不能用”
    
- CLS → 看“稳不稳”
    

---

# 🚀 三、加载性能优化（最重要）

## ✅ 1. 减少资源体积

- 压缩 JS / CSS
    
- Tree Shaking
    
- 使用 Vite 自动优化
    

---

## ✅ 2. 代码拆分（Code Splitting）

```js
const Page = React.lazy(() => import('./Page'))
```

👉 首屏只加载必要代码

---

## ✅ 3. 懒加载

- 图片懒加载
    
- 路由懒加载
    

---

## ✅ 4. CDN 加速

👉 静态资源走 CDN

---

## ✅ 5. 缓存策略

- 强缓存（Cache-Control）
    
- 协商缓存（ETag）
    

---

## ✅ 6. SSR / SSG（你刚问的）

👉 解决白屏问题

- Next.js
    
- Nuxt.js
    

---

## ✅ 7. 骨架屏（非常实用）

👉 提升“感知速度”

---

# ⚡ 四、渲染性能优化

## ✅ 1. 减少 DOM 操作

❌ 不要频繁操作 DOM  
✅ 批量更新

---

## ✅ 2. 避免重排（Reflow）

影响性能的操作：

- 改 width / height
    
- 改布局
    

👉 用 transform 替代

---

## ✅ 3. 使用 GPU 加速

```css
transform: translateZ(0);
```

---

## ✅ 4. 虚拟列表（大数据量）

👉 只渲染可视区域

---

# 🧩 五、交互性能优化

## ✅ 1. 防抖 / 节流

```js
debounce(fn, 300)
throttle(fn, 300)
```

---

## ✅ 2. Web Worker

👉 把计算丢到子线程

---

## ✅ 3. 事件优化

- 事件委托
    
- 减少监听器
    

---

## ✅ 4. 长任务拆分

👉 避免主线程卡死

---

# 🌐 六、网络层优化（很多人忽略）

## ✅ 1. 减少请求数量

- 合并接口
    
- GraphQL（可选）
    

---

## ✅ 2. HTTP/2 / HTTP/3

👉 多路复用更快

---

## ✅ 3. 预加载

```html
<link rel="preload">
<link rel="prefetch">
```

---

## ✅ 4. DNS 预解析

```html
<link rel="dns-prefetch">
```

---

- 防抖节流
    
- Web Worker
